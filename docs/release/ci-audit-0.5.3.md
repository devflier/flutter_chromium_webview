# Release CI audit — 2026-10-14 (before implementation)

Reviewed the single unified workflow, every platform validation script, both packages and both example pubspecs, override files, exports, and two macOS artifact sets from run 38554492568.

- Both macOS attempts passed 22/24 stages. The app, VM service, native test binding, host, CEF and eleven deterministic integration suites ran successfully. Foreground activation warnings did not prevent those tests.
- Real YouTube reported error 150 with explicit `Sign_in_to_confirm_you_re_not_a_bot` responses. Allocation profiling calls `playing()` before starting its clock/DevTools observer. Media readiness failed (attempt 1 invalid numeric result; attempt 2 error150), so it recorded zero active samples. This is no memory verdict, not profiler permission/attachment evidence.
- The allocation fixture defaults to YouTube; animated/static alternatives do not decode video. The existing collector selects the host and recursive descendants; helper roles are captured. It measures RSS and rendering/video counters, not allocator ownership or an Instruments trace. Calling it an allocation profile does not establish exact allocations.
- Both publishers depend on quality plus Linux, Windows, Android and macOS. Interface publication is therefore gated on an unrelated remote media service and native soak. Its own relevant checks are abstract/method-channel API tests, exported types, example backend tests, analyzer, package dry run and compatibility with the main consumer.
- Monorepo quality uses local interface overrides. Published 0.1.5 lacks evaluate/cancel JavaScript, pointer click count and native browserCrash forwarding used by the plugin. Version 0.1.6 is necessary. Main upload has additional public-resolution checks, but readiness should expose them before a tag/publication attempt.
- Main/example overrides are now excluded from the plugin archive. Example ordinary pubspec no longer points to a missing sibling. Interface SDK permits local Dart3.12; plugin SDK requires3.13. Existing Flutter3.44.8/Dart3.12.2 cannot validate that package unchanged.
- macOS was skipped for ordinary PR/main pushes. Manual runs plus PR runs duplicated whole-platform work; tag runs repeated again. Interface tags unnecessarily ran all native jobs. No job should use `continue-on-error` to convert a failing required gate into success.
- Legacy profiling assertion compares second active sample with final active combined CEF RSS, strict `<75000 KiB`. Historical cold-to-warm/repeated-session failures remain distinct and failed. Deterministic media results must not retroactively certify YouTube or long-term stability.

Plan: independently gate interface/API compatibility; keep plugin native jobs required; separate deterministic macOS core, local decoded-media RSS/resource acceptance and explicit live-service job.
