# Repository audit — 2026-10-04

## Verdict

The project is an experimental implementation, not release-ready. The Dart layer passes its current checks and Windows compiles, but native runtime validation remains blocked. Stabilize startup, resource ownership, input and shutdown before adding features.

This audit reviewed the current Windows checkout, including staged, unstaged and untracked source. No application source was changed. Flutter 3.47.4 / Dart 3.13.3 were used. There are no Git commits or configured remotes, so results cannot be tied to an immutable revision. The existing September Linux results came from a separate WSL checkout and are historical evidence only.

## Findings

### P1 — Windows textures expose mutable memory to the raster thread

`windows/cef_texture.cpp:17–48` updates the same vector returned by `CopyPixels`. Its mutex is released before Flutter consumes the returned pixels; subsequent paints can overwrite them or resize the vector and invalidate its address. No release callback or independent frame snapshot protects that memory. `windows/cef_browser_handler.cpp:19–20, 78–79` also deletes textures separately from confirmation of asynchronous unregistration.

Use frame ownership that lasts through engine consumption and texture-unregistration completion. Add native regressions for painting/resizing during sampling and closing while a frame is in flight. The Windows allocation expression also performs signed `width * height * 4` without the Linux implementation's dimension checks; port those guards.

### P1 — Windows lifecycle does not fulfill the public disposal contract

`windows/flutter_chromium_webview_plugin.cpp:204–217` replies to disposal immediately after requesting `CloseBrowser`, rather than using the handler's completion callback. Session replacement similarly clears the map and returns while previous browsers are closing (`113–124`). The `resetting_` member is never set true. `CefRuntimeManager::Shutdown()` has no call site in the Windows implementation. The window-procedure delegate registration is not paired with unregistration.

Wait for `OnBeforeClose` before completing disposal/session reset, retain resources through that transition, and wire orderly application shutdown and delegate cleanup. Verify zero browser/texture counts after each disposal, hot restart, and normal window close.

### P1 — Windows focus and keyboard input are unfinished

`windows/flutter_chromium_webview_plugin.cpp:255–256` acknowledges `setFocus` while doing nothing. The window-procedure delegate is also a stub, and the Windows source has no keyboard event forwarding. Diagnostics always report `focused: false` (`133`). Thus the registered Windows plugin cannot meet the existing lifecycle/focus integration test's expectations even after startup is repaired.

Implement browser focus ownership and native keyboard/clipboard input. Validate typing, shortcuts, Tab traversal, Unicode and two-browser focus isolation.

### P1 — Windows resource layout and sandbox configuration need resolution

`windows/CMakeLists.txt:99–103` bundles locale PAK files beside the executable; `windows/cef_runtime_manager.cpp:70` looks in a `locales` subdirectory. The actual debug bundle confirms PAK files at the root and no locales directory. Align installation and runtime paths, then test the copied bundle outside the checkout.

`windows/DownloadCEF.cmake:67` forces `USE_SANDBOX OFF`, while runtime code claims sandboxing is enabled and passes no Windows sandbox information to CEF. This is inconsistent configuration, not evidence of working confinement. Establish the intended supported configuration and validate it without an automatic security-disabling fallback.

### P2 — Dropdowns painted beyond the widget cannot receive ordinary hits there

The Dart widget paints popup textures through a `Stack(clipBehavior: Clip.none)` within its viewport-sized `Listener` (`lib/flutter_chromium_webview.dart:741–775`). Painting overflow does not enlarge ancestor hit-test bounds. A dropdown extending beyond the viewport has no corresponding input surface outside it.

Use an overlay with input routing or constrain the popup to an interactive viewport. Verify every edge, resize/DPR changes and dismissal. Existing controller-level pointer injection tests do not verify widget hit testing.

### P2 — Release documentation and package contents are inconsistent

- README says Windows is planned despite registered, compiling Windows code. Describe it as incomplete/experimental with failed runtime validation.
- Root README says sandboxing is disabled; security documentation says enabled. State the verified status per platform.
- CONTRIBUTING lists older Flutter requirements than `pubspec.yaml`, and says native tests are unavailable despite an opt-in native suite and passing historical log.
- Publication dry run includes the entire unused `example/dummy_plugin` scaffold. Exclude or remove it from the package archive after checking intent.
- The separate platform-interface package still contains only a generated `Calculator`; the main package uses its own interface and direct browser channel. Decide whether to remove the unused package or implement a real shared interface.
- No CI workflow was found. Many implementation/docs files are untracked, and the repository has no initial commit or remote.

## Recommended next work

1. **Make native startup diagnosable and reliable.** Capture Windows application/subprocess stderr, CEF logs and native exit information; resolve the integration termination. Correct the locale layout and establish the Windows sandbox configuration. Exit criterion: lifecycle integration reaches its assertions consistently.
2. **Repair Windows frame ownership and lifecycle.** Implement retained frames, dimension guards, confirmed disposal/session reset, texture cleanup and shutdown. Exit criterion: repeated resize/create/dispose, hot restart and normal close pass with no leftover resources/processes.
3. **Complete Windows input.** Implement focus, keyboard and clipboard forwarding, then run lifecycle, input-scaling and native-UI integration suites individually and together.
4. **Close the Linux release gates.** Rerun all current suites from a synchronized checkout, investigate the historical launch failures, and validate debug/release with default graphics and the software baseline. Verify copied-bundle interaction and clean shutdown, then obtain native Linux desktop evidence.
5. **Resolve popup input and pending host UI.** Test dropdown overflow and host dialog/menu cancellation on navigation/disposal with two browsers; verify physical IME and clipboard manually.
6. **Make release evidence reproducible.** Align docs and supported versions, clean package contents, add repository metadata and CI, and create a reviewed initial Git baseline. Rerun publication dry run from a clean state and attach validation to that revision.

The next implementation milestone should be reliable native startup and lifecycle, followed by input parity. A successful compile and mocked Dart tests do not close the runtime release gates.

## Implementation follow-up — 2026-10-04

The findings above describe the initial audit. The authorized stabilization pass
implemented Windows sandbox bootstrap startup, matching locale paths, immutable
raster frame leases, confirmed browser disposal/session reset, texture cleanup,
normal shutdown, focus ownership and native keyboard/IME forwarding. Windows
initialization now logs CEF's exit code and failures cannot trigger a second CEF
initialization attempt. Linux initialization is also terminal after failure.

Dropdown input now uses a following overlay outside the browser's viewport, and
the example cancels pending dialog/menu routes for their owning browser. Returning
focus after a dialog refreshes CEF focus even when ownership has not changed.
Copied Linux release testing exposed a nested GLib pump freeze; enabling CEF's
external pump restored window events and clean shutdown.
The Windows copied-bundle check also found a Flutter teardown access violation:
clearing a channel handler after the engine stopped used a destroyed dispatcher.
The plugin now retains/checks the native messenger before clearing handlers.
The smoke regression requires zero exit status as well as CEF shutdown completion.

Validation passed: both analyzers, 17 package tests, 2 example tests, all four
Windows integration suites and all three Linux suites in WSLg, native frame tests,
and both release builds. Copied bundles started and closed normally with shutdown
completion and no CEF subprocesses left behind. WSLg software/default graphics
both passed this smoke check; default graphics still reports DRI3 warnings.
Raw evidence is retained in `docs/validation`, and the current matrix is in
`docs/release-readiness.md`.

Validation scripts, bundle packaging scripts, Windows runner instructions and
Dart/Windows CI were added. The publication dry run excludes the unused scaffold
and build output; its remaining warnings concern the uncommitted tree and missing
repository/homepage metadata. No package was published.

Next gates: physical clipboard/IME and multi-monitor/edge-popup testing, native
Linux testing outside WSLg, deployment sandbox/notice/signing review, a real
repository URL, a reviewed Git baseline and a remote CI run. The independent
Calculator platform-interface scaffold remains unused and should be resolved
before designing a federated package release. The project remains experimental.
